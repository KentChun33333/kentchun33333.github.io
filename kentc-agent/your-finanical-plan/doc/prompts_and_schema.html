1. How Each Solution Path Handles Prompt Construction

All 4 lanes share the same YAML-compiled System Prompt and compact JSON output protocol, while injecting a tailored solution_contexts preamble and input payload format.

Lane A · Excel Cell-Only Parser

Serializes every non-empty worksheet into pipe-delimited Markdown rows (col1 | col2 | ...), repeating sheet title & header row on split chunks (≤12,000 chars). Zero OCR and zero vision tokens.

solution_mode: excel text-only Qwen3.8 only

Lane B · Small PDF (≤ 9 pages)

Extracts embedded text via PyMuPDF (calling PaddleOCR only if a page has <60 chars). Packs 3–5 pages per call with explicit ### [Page N | page=N] boundaries so mixed pages classify independently.

solution_mode: small_pdf pages_per_call: 4 mixed-doc aware

Lane C · Large PDF (> 9p Triage)

Loads triage_keywords from extraction_schema.yaml to score PaddleOCR/PyMuPDF pages, drops legal T&C, and sends only top-K numeric pages (3–5 pages/chunk) with a focused insurance/brokerage preamble.

solution_mode: large_pdf_triage PaddleOCR triage top-8 pages

Lane D · Images & WebM Media

Decodes HEIC/WEBM/JPG/PNG/WEBP, clamps to ≤1024px, runs row-aligned local PaddleOCR, and sends both the aligned OCR text and the 1024px JPEG image URL to Qwen3.8 multimodal vision for column cross-checking.

solution_mode: image_media OCR + Vision ≤1024px JPEG

2. Prompt Architecture Summary (System + Per-Solution User + Output Protocol)

Compiled dynamically at runtime by build_system_prompt() and build_user_prompt() in solutions/qwen_client.py.

A. Compiled System Prompt Structure

[role_instruction from extraction_schema.yaml]
Allowed `document_type` categories: investment | funding | bank_statement | insurance | liability | income_tax | real_estate | other

Key Definitions by `document_type`:
- <primary hinted doc_type first (full key: definition list + extraction_rule)>
- <all other doc_types (full definitions when auto-detect, or compact key list when hinted, so mixed pages still classify accurately)>

Rules:
1. Assign best-fitting `document_type` PER ROW (supports mixed PDF/Excel).
2. Extract concrete numbers from ALL sections shown; never invent numbers.
3. Prefer standardized `metric_key` names from YAML definitions.
4. Preserve exact `value_raw` + ISO `currency` + `unit` + `as_of_date`.
5. Put concise context (round, broker, term, unit price) in `notes`.

Output ONLY compact minified JSON (cuts output tokens ~75% for <50s SLA):
{"r":[["doc_type","section_or_sheet",page_int,"entity_or_ticker","metric_key","value_raw","currency","unit","as_of_date","notes"],...]}

B. Per-Solution User Prompt Payload Template

Client: {client_name} | File: {source_file} | Pipeline: {excel | small_pdf | large_pdf_triage | image_media}
Optional hint: document_type='{doc_type_hint}' (or Auto-detect per row)
Context: {prompt_settings.solution_contexts[solution_mode]}
Extract key financial numbers from ALL sections below into compact JSON {"r":[[...]]}:

### [{section_or_sheet} | page={page_number}]
{pipe-delimited Excel rows OR PyMuPDF text OR row-bucketed PaddleOCR text}
[+ base64 1024px JPEG image_url when solution_mode == image_media]

C. Local PaddleOCR Prompt (Optional Ollama PaddleOCR-VL Engine)

Default engine (`rapidocr`): Deterministic PP-OCR ONNX det + rec + row-bucketing (y_bucket = round(y / 14px), joined by " | ") — zero LLM tokens.
Optional Ollama engine (`ollama_paddleocr` / MedAIBase/PaddleOCR-VL:0.9b): prompt = "OCR:", temperature = 0, image <= 1024px.
