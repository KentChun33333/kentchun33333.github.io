舊對話累積到門檻時，KentC 先存檔，再請模型寫一份供下輪接手的 checkpoint。過大的新輸入或工具結果會另外外存。每輪只把當下需要的訊息、摘要與索引提示送給模型。

01 · 進入上下文之前

不同輸入會走哪一條路？

使用者輸入、文件、工具結果與累積歷史
輸入情境模型先收到什麼完整資料在哪裡
一般 prompt 或對話原文作為 user 訊息。第一則 prompt 也遵循同一規則，日後可能被摘要。啟用 session 紀錄時寫入 JSONL。移出有效對話時也會寫入歷史存檔。
很長的貼文或文字附件有 read 或 bash 的主代理會比較每個文字輸入部分的大小與門檻 max(512, min(big_turn_tokens, floor(W / 5)))。超過時改送首尾預覽和回讀路徑。CLI 文字附件與 prompt 組合後再做這個判斷。全文寫入 input 存檔，索引來源標為 user 訊息 ID。缺少回讀工具時，程式直接保留輸入，交由請求預檢判斷能否送出。
明確固定的要求--requirement 或 /require 固定的文字，每輪原樣送出，佔用上下文。可用 /requirements 檢視並用 /unrequire 移除。與對話分開記錄的 session 事件。一般聊天可以直接下 prompt，只有希望某條要求始終原樣帶入時才需要固定。
讀取一般文字檔小檔回傳文字。指定 offset/limit 或 start_char/max_chars 時只回傳限量片段。整檔結果超過單筆預算時，回傳規則摘要與回讀位置。原檔仍在。大型結果另保存讀取當下的 full.md 和 digest.json，索引列出快照。
PDF、圖片、Office 等文件PDF、圖片走解析路徑，支援提問或轉錄。Office 等文件先轉文字，小結果直接返回，大結果可交給解析子代理整理。文件原檔與解析輸出分開。可用 question 查具體事實、用 PDF pages 限定頁面，或在轉換後的 full.md 按行回讀。
大量命令、搜尋或錯誤輸出單筆超限先外存。整批仍超限時，優先外存尚可縮小的最大筆結果。大型錯誤也走外存，保留錯誤標示。結果檔和索引仍可回讀。一般結果使用規則摘要。批次超限本身不會啟動通用子代理，有文件來源的候選可走文件解析。
模型寫入或編輯長文件write 或 edit 仍須先在單輪輸出額度內產生完整 JSON。執行成功後，超過 max(512, 單筆結果預算) 的大型參數會以歷史參照取代，保留目標路徑、呼叫 ID 和成功回傳。寫檔失敗時保留原參數。原始參數寫入 arguments 存檔，可從索引找回。回讀目前的正文則使用目標檔。重開 session 時會恢復捷徑。
對話歷史累積較舊的訊息由 checkpoint 接手，近期訊息留在有效對話中。history 存檔保存這次移出的訊息與上一份摘要。若訊息本身已是外存指標，可再沿索引找原文。

02 · 每次主模型請求前

何時觸發歷史壓縮？

工作視窗 W 取部署上限和已啟用的工作上限中的較小值。R 是壓縮保留量，K 是保留近期訊息的目標。以下採程式預設的保留量和輸出設定，並以 density = 1 示範。

示例工作視窗 W60,000
壓縮保留量 R15,000
一般壓縮門檻 W − R45,000
近期保留目標 K20,000
依照當下的預算或錯誤選擇處理
觸發情境判斷與動作
正常累積T + F > W − R 就嘗試壓縮。以本例而言，T = 44,500 加上狀態提示的預留量 F = 512 已達 45,012，會先嘗試壓縮。
回覆空間偏小若 room = W − T − M − F 小於 1,024，嘗試強制壓縮。M = max(256, floor(W / 20)) 是安全餘裕。
組好完整請求後仍太大用系統提示、工具 schema、有效訊息、當輪狀態與可能的重試指示再估算。扣除安全餘裕後低於 512 tokens 時，這道預檢額外嘗試一次強制壓縮，仍不足則在本機報超限。
伺服器回報超限若只是輸出額度太大且仍有足夠空間，先縮減 max_tokens 重試。若輸入本身過長或再次超限，強制壓縮。第三次超限時回報錯誤。
手動操作CLI /compact [focus] 強制嘗試壓縮。可加焦點提示，指定這次摘要應特別保留的資訊。若沒有合法切點，可能沒有新的 checkpoint。
估算 T 與 density 的細節

T = C + ceil(E × density)。C 是最近有 usage 的有效回覆所回報的輸入與輸出總量。E 估算其後的訊息。若沒有可用 usage，例如剛壓縮完，則一起估算固定提示、工具 schema 和全部有效訊息。

文字從每四字元約一個 token 起算，還會估入工具參數、推理內容與圖片配額。當 E ≥ 300 且伺服器輸入量 P > C 時，觀測值是 min(3, (P − C) / E)。較高的密度立即採用，較低的值用 max(1, 0.8 × 舊值 + 0.2 × 觀測值) 平滑更新。

主代理的 F = ceil(512 × density)。保留量 R = min(reserve_tokens, floor(W / 4))，近期保留目標 K = min(keep_recent_tokens, floor(W / 3))。

03 · 歷史如何移出有效對話

找切點 → 存檔 → 寫摘要 → 重建

  1. 1．保留近期訊息從尾端往回累加估算，目標約為 K。切點落在 user 或 assistant 訊息的開頭，維持工具呼叫與回傳的配對。
  2. 2．保存將移出的訊息先存上一份 checkpoint 與切點前的訊息，保留現有的參數或外存路徑。索引標明存檔涵蓋到哪個訊息 ID。
  3. 3．生成或更新 checkpoint第一次從舊訊息寫摘要。已有摘要時，把上一份摘要與本次移出的訊息一起交給模型。
  4. 4．確認摘要可用後提交寫入 compaction 事件，記錄摘要與第一個保留訊息的 ID。重新載入時由 JSONL 重建有效對話。

強制模式在一般切點找不到時，可改在最後一個 user 或 assistant 訊息前切分。如果保留內容仍超過強制壓縮的預算，而且最新訊息的角色不是 user，程式也可將整段有效對話移出，只留下新的 checkpoint。

摘要失敗或空間仍不足

摘要回傳空白或因長度截斷時，同一批資料以 effort=none 再試一次。仍失敗就保留原本的有效對話與摘要。自動流程遇到摘要錯誤或上下文超限時會記錄狀態。強制騰空時，可把過大的舊工具結果另存，再以回讀指標取代 live 內容。這項替換寫入 session log，重開後也會套用。

實作對照 切點與摘要呼叫歷史存檔與緊急外存事件與重建

04 · 模型怎麼寫 checkpoint

摘要使用固定的 Markdown 章節

模型讀到的資料

<conversation> 包住本次移出的舊訊息，標記使用者、助理、工具呼叫與工具結果。單筆工具結果最多提供開頭 2,000 字元，再標記省略量。圖片部分以 [image] 表示。摘要輸入不包含助理的推理欄位。

有上一份摘要時另加 <previous-summary>。如果序列化後仍太長，就依預算切成多塊，優先找段落邊界。每塊用前一塊生成的摘要繼續更新。

模型收到的寫作指示

系統提示要求模型只寫交接摘要。已有 checkpoint 時，保留仍相關的內容，補上進度與新發現，有完成檢查才移入 Done，並更新下一步。手動壓縮指定的 focus 也會加進提示。

輸出上限是 min(floor(0.8 × R), max_output_tokens)。另外以提示要求字數低於 floor(3 × clamp(floor(W / 16), 300, 4000) / 4)。本頁的 60,000 視窗示例是 8,192 輸出 tokens 和 2,812 words。

程式要求的八個章節
章節寫入內容
Goal使用者想達成的任務。若同一 session 含多個任務，可以分項。
Constraints & Preferences使用者提出的要求與偏好。盡量保存會影響結果的原句。
Completion Requirements要稱為完成之前，必須滿足的條件和檢查。
Progress分成 Done、In Progress、Blocked。已完成事項附上確認依據。
Evidence觀察結果、驗證狀態、精確檔案與範圍，或工作區索引 ID。
Decisions & Exploration決策與短理由、應避開的失敗嘗試，以及標明仍待驗證的假設。
Next Steps下一輪應先做哪些動作。
Critical Context接手需要的路徑、函式名、識別碼、數值與錯誤訊息。

05 · 壓縮後如何接手

模型看見摘要，精確資料從磁碟取回

下一輪請求依序帶入系統提示、當輪狀態提示、最新 checkpoint、有效的固定要求與近期對話。工具定義也會佔用預算。狀態提示顯示索引路徑與最近三筆記錄，完整索引按需讀取。

重開 session 時從哪裡找回資料
需要的資料回讀位置
使用者原始 prompt短文字可從 JSONL 或歷史存檔找回。超長文字查 input 索引。現行實作會把早期 prompt 納入一般壓縮，沒有自動把第一則 prompt 原樣注入每一輪。
完整工具結果透過索引 ID 或來源找到 full.md 或緊急外存結果。用行範圍或字元範圍回讀。
進度和完成條件CLI 聊天可用 task_state 的 show 取回已保存的里程碑。Workflow 從該次執行的 state.json 恢復狀態，仍由設定的檢查判定完成。
已記錄的證據沿里程碑的證據 ID 到索引找引文快照及來源範圍。程式確認引文曾在指定位置，證據是否足以滿足完成條件仍由 agent 判斷。
