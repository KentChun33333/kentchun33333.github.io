00 · 同一個代理，三種使用層

越無人看管，權限越收斂

問題

同一代理服務三種場合：終端逐回合確認、無人看管的長流程、處理他人上傳文件的網頁應用。單一權限組不是過寬就是過窄。

核心想法

單一核心代理，依看管程度決定工具、網路與輸出格式。越無人看管 → 工具越少、網路越受控、輸出越結構化。

依據

限制在載入檢查強制，不靠提示：工作流程步驟列出 web_search、Studio 代理宣告 bash，載入即拒絕。

問題：三種風險

CLI 對話：逐回合有人看，錯誤即時可中止 → 工具可最多。工作流程：長時間無人看管 → 一次錯誤查詢或網頁注入可無聲污染後續多步。Studio：輸入為他人上傳文件，可夾帶「忽略之前的指示」；輸出直達分析師。

例：Studio 有 bash → 注入可觸及 shell；CLI 降到 Studio 權限 → 互動處處受限。

核心想法：權限隨看管程度收斂

CLI 對話

人在迴圈中，逐回合確認

read、write、edit、bash ＋ 經篩選的 web_search（提問觸發；結果經篩選子代理與安全檢查才進對話）。--tools 可縮減。

成果：直接回答、工作區檔案。

工作流程

長時間、自主執行

主代理僅四個核心工具，無 web_search；外部資料走 web: 步驟，由網路代理篩選、限搜尋預算、查核連結、人工核准。

成果：檔案（research/、notes/、reports/），可 --resume。

Studio

網頁體驗，系統定義輸入與輸出

讀上傳文件與 SQL 擷取資料；只讀案件資料夾、永無 bash、無網路。每應用一份 config/apps/<name>/app.yaml 即工作流程：宣告代理契約、技能、output 與 checks，由 view 以固定區塊呈現。

成果：結構化 JSON → 前端區塊（代理不產生 HTML）。

頁面流程、技能路徑、報告框架欄位、view 檢查：詳見 10 · Studio 應用。

依據：載入時強制，不靠提示

  • 工作流程：外部資料只經 web: 步驟（詳見 09 · 網路研究）。
  • Studio：無 web: 步驟；其餘設定錯誤亦於啟動時拒絕，不延到畫面（詳見 10 · Studio 應用）。
  • 邊界：工具清單 ≠ OS 沙箱。write／edit 限工作區路徑，bash 仍具執行程序權限（見 08 · 工作流程）。
