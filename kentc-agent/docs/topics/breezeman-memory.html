B2 · 跨會話長期記憶與離線 Dreaming 蒸餾

O(1) 快篩、BM25 兩階段檢索與三軌冪等寫入

問題

跨會話運行數月後會同時撞上三道牆：數百份 .jsonl 全量重讀拖垮 I/O；memory/INDEX.md 膨脹撐爆視窗；分塊重跑灌水 verified_count；Dreaming 故障時每 5 秒無限空轉。

核心想法

離線 Dreaming 採 O(1) stat() 快篩 → 視窗預算分塊 → 純 Python BM25 Top-K → 三軌冪等寫入（Fact / Pattern / SIM）→ 有界 L0 Manifest，並具備獨立退避與熔斷；零外部向量庫依賴。

依據

實作於 memory_store.py、dream.py 與 runtime.py，由 test_breezeman_dream.py 完整驗證。

問題：跨會話記憶與單任務記憶的本質差異

kentc_agent 內部的 session topic notes 只服務「單一任務的壓縮回溯」；但使用者偏好、專案架構決策、跨任務可重用的除錯配方，以及不同本機模型的失敗教訓（SIM），需要跨所有 Task 與 Studio 共享。然而一旦跨月累積，直接把所有筆記塞進提示或全量掃描所有歷史 journal 都會迅速失控。

核心想法一：五階段 Dreaming 離線蒸餾管線

圖 B2-1：Dreaming 離線蒸餾管線。無須外部向量資料庫，僅靠純 Python Okapi BM25 與 O(1) stat 快篩即可穩定支撐長程擴展。

核心想法二：三軌知識模型與各自生命週期

Track A · Facts

事實與偏好（facts/）

記錄使用者偏好、角色、專案架構與長期決策。新事實若宣告 supersedes_id，舊節點會標記 superseded、寫入 valid_until 與 superseded_by 並自動移入 archive/。

語法：<Subject> is/uses/prefers <value>.

Track B · Patterns

可重用配方（patterns/）

首次抽取為 provisional；透過 verified_sessions 記錄來源 session ID，同一 session 重跑不會重複灌水，必須在不同 session 驗證達 verified_count ≥ 2 才升級為 active / verified。

超過 60 天未更新的 provisional 節點會由 optimize_memory() 自動歸檔。

Track C · SIM

自我改進記憶（sim/）

記錄模型與工具策略的成功／失敗帳本（含 models_tested），採純追加 ### [YYYY-MM-DD]。當超過 2,000 tokens 或 8 條紀錄時觸發 LSM Seal & Roll：舊紀錄封存至 archive/sim/<slug>-log.md，活頭蒸餾為 Active Strategy ＋ Known Pitfalls ＋ 最近 3 筆。

詳見 kentc_agent 分頁 08 · LSM 分層封存。
