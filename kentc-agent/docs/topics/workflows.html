09 · Finite-State Workflow 確定性狀態機（src/kentc_agent/fsm_workflow.py）

同一隻 Agent 加上前後護欄：從 Main Agent 到 State-Machine Agent

問題

線性步驟無法回跳修正；共用長對話會造成 REVIEW 球員兼裁判與上下文膨脹；小型本機模型常出現 false DONE（自稱測試通過但真實 exit code 非 0）。

核心想法

以 Finite-State Workflow（fsm_workflow.py） 統一工作流程引擎：100% 純 fresh（每個 state 是套上 Precondition / Postcondition 的同一隻 kentc_agent.Agent，靠磁碟 Artifact 交接）、獨立 Runtime Validator 取真實證據、零模型呼叫 exit_gate 把關 DONE。

依據

實作於 src/kentc_agent/fsm_workflow.py，涵蓋 7 份內建 YAML（含 coding-loop.yaml），整合進 Breezeman 排程與頂部 Workflows 設定專區，由 tests/test_fsm_workflow.py 完整驗證。

四種 State 類型與客觀 Validator 清單

四種 State 類型

  • prompt: — 新鮮 Agent 執行任務，可搭 skills:、tools:、format: json、schema:、checks:、output:。
  • gate: true — 零模型呼叫的確定性閘門，僅跑 validators: 決定 passed / failed。
  • ask: — 人工審核門（非互動時拋 NeedsAnswer，以 --resume --answer 或 Breezeman UI 續跑），依回答直接路由。
  • web: — 隔離網路研究子代理（支援 plan、foreach 與 approve: true），簡報落盤交付。

獨立 Runtime Validators

  • command: — 由 runtime 在工作區直接執行命令，exit_code == 0 才算通過。
  • file_exists: — 驗證目標產出檔確實存在於工作區且非空。
  • git_diff: true — 驗證工作區確實有實際變更。
  • expr: — 針對 step_data、data、steps 與 evidence 的確定性布林檢查。
