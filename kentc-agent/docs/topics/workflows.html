08 · 用工作流程約束方法，不建立代理團隊

同一個 Agent，依階段改變指示與工具清單

問題

長任務需要固定順序、人工審核與中斷續跑。單一大提示 → 步驟遺漏、權限無法分段、失敗只能重來。

核心想法

YAML 定義步驟，Runner 依序執行同一個代理，每步只換指示、工具與輸出約定。人類決策用 ask；狀態存檔，可從未完成步驟續跑；不建多代理團隊。

依據

回歸測試涵蓋：呼叫次數用盡即失敗且不寫 output；輸入錯誤明確報錯，--resume 可覆寫輸入。實際使用問題已修正（見 ③）。

問題：單一大提示撐不起長任務

  • 順序與完整性：「讀文件、核對數字、等人確認、寫報告」交由模型安排 → 小模型常跳過核對直接撰寫。
  • 權限不分：撰寫不需 bash，擷取不需寫檔；全程同一組工具 → 敏感階段無法收緊。
  • 人工審核：模型不得自稱「已獲批准」→ 需要真正停下等人的點。
  • 中斷：一小時的任務在第四步失敗，不應從第一步重來。

多代理分工 → 每次交接重傳脈絡，資訊散落、責任不清，小模型更吃力（見 01 · 方法論）。

核心想法：步驟化的同一個代理

對話脈絡全程沿用，必要時壓縮。分支用 when，網路研究用 web（見下一篇）。有 output 的步驟告知代理「最終回覆由 Runner 存檔」，後續步驟直接讀。

示範：從證據到一份可核對的摘要

教學流程 · 非內建業務流程
# 示範 YAML：所有模板變數均有定義
name: evidence-brief
# 文件就是工作區（-w）裡的檔案：不需要資料夾參數
instructions: |
  使用繁體中文。區分原文明示與推論。
  每個重要事實標示檔名與位置；數值用工具計算。
tools: [read, bash]
steps:
  - id: extract
    tools: [read, bash]
    prompt: "讀取 {{ documents('.') | join(', ') }}，整理事實、位置與缺口。"
  - id: check
    tools: [read, bash]
    prompt: "核對前一步的關鍵數字與引文；不確定之處明確列出。"
  - id: review
    ask: "請確認核對結果，或輸入修正要求："
  - id: brief
    tools: []
    prompt: "依證據與審閱意見撰寫摘要；不足之處不可補猜。"
    output: reports/brief.md

步驟切分的理由

  1. 擷取與核對需要工具查找與精確計算有實際執行路徑。
  2. 審閱是明確決策點未答即停、之後恢復；模型不得冒充批准。
  3. 撰稿只用已得證據tools: []；output 由 Runner 存，無需 write。

結構化輸出：format: json ＋ schema；不符重試一次。

state.json（步驟結果、決策）＋ session.jsonl（對話）→ --resume 從未完成步驟續跑。

工具清單不是作業系統沙箱。 只限本步驟可用工具；write／edit 受工作區路徑限制，bash 仍具執行程序權限。

依據：測試與實際使用後的修正

  • 失敗不留半成品：用完 max_turns → 「no final answer within max_turns」失敗，不寫 output（test_untrusted_inputs.py）。
  • 輸入錯誤可修正續跑：文件資料夾不存在 → 明確報錯；--resume latest -i KEY=VALUE 覆寫輸入，已完成步驟保留（同上）。
  • 實際使用的修正：「工作區即文件資料夾」（移除 docs_dir 等路徑參數）、有 output 步驟告知「回覆由 Runner 存檔」。詳見 09 · 網路研究。
