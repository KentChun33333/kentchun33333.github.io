04 · 上下文視窗的兩個方向

跨回合壓縮歷史；單回合控制新資料

問題

視窗約 6 萬 tokens，一件審查案的原始資料就接近一整個視窗。指令輸出與推理逐輪累積（縱向）；單次讀檔或搜尋也可能一次塞滿（橫向）。

核心想法

縱向：超過門檻前將舊歷史壓成摘要，保留最近訊息。橫向：結果進入上下文前判斷大小，大型結果存磁碟，只給模型摘要與可再讀路徑。

依據

歷史實測（舊版 v1，已移除）一次 STR 任務：prompt 從 2,136 長到 45,533 tokens，第 74 次呼叫觸發壓縮，全程送出約 240 萬 prompt tokens。記憶回復一次壓縮 65,594 → 19,764（③）。

問題：視窗固定，資料量不固定

本機 W = 62,536 tokens，須扣回覆空間、系統提示、工具說明；超過 W − R（R：壓縮保留量）須先騰空間。預設值下可累積對話上限 ≈ 46,902 tokens。

縱向問題

談得越久，歷史越長

每次「呼叫工具 → 讀結果 → 推理」都留在對話。80 次呼叫、每次僅增數百 tokens，幾十次後即撞門檻。直接截掉舊訊息 → 遺忘已查過、已決定的事。

橫向問題

一次讀太多，當下就放不下

大檔 read、數千行 grep、多頁 PDF：單回合結果即可能超過剩餘空間。

核心想法：縱向壓縮歷史，橫向外存大型結果

縱向 · compaction.py

歷史太長：壓縮舊對話

保留最近訊息，較舊內容整理成短 checkpoint＋本地主題筆記，合組下一次請求；磁碟原始對話保留。

不刪工作區檔案，不把資料訓練進模型。

橫向 · bigcontext.py

本輪太大：大型結果外存

單筆或批次超預算 → 保留完整內容或來源參照，給模型摘要 + 可再讀路徑。

壓縮舊歷史救不了：問題在新進資料。

token 估算不是字數 ÷ 4

下一次輸入估算 = C + ceil(E × density)：C 為最新伺服器 usage 錨定的已計數部分，E 為其後新訊息估算。無計數時，系統提示、工具 schema、摘要、對話皆估算。伺服器實際輸入量校準 density；影像仍有模型相關誤差。

上下文預算教學計算器

示意參數，不是代理設定

W 僅模擬伺服器回報值；頁面不連線、不偵測模型、不改 config，其餘保留策略用程式預設值。

藍色：壓縮門檻前的範圍 · 紅色：保留區 · 黑線：目前估算位置（超過 W 時停在右緣）

展開預算公式與限制
R = min(16,384, floor(W / 4)) 壓縮保留量 K = min(20,000, floor(W / 3)) 最近訊息保留目標 M = max(256, floor(W / 20)) 請求安全餘裕 room = W − T − M 回覆可用空間 T > W − R 先嘗試壓縮 room < 1,024 嘗試強制壓縮 max_tokens = max(512, min(O, room)) 主迴圈初步請求值；之後還可能依超限回覆調整

最低 512 不保證放得下：壓縮仍騰不出空間 → 伺服器可能拒絕；計算器不標為「已安全送出」。摘要只有篇幅目標與輸出預算，無固定長度。

壓縮的輸入、處理與輸出

  1. 找切點從最近訊息往回估算，切在使用者或 assistant 訊息；工具結果不與其呼叫分開。
  2. 更新 checkpoint 與主題舊訊息 + 上份 checkpoint → Goal／Constraints／Progress／Key Decisions／Evidence／Next Steps／Critical Context，細節寫入主題筆記（見 07）。
  3. 重建工作上下文以「checkpoint ＋ 固定需求 ＋ 筆記索引 ＋ 最近訊息」繼續；原始訊息留 session 日誌，不全部重送。
  4. 壓縮失敗不假裝成功回報問題、保留完整歷史，不截短舊工具結果；送出前估算回覆空間不足 512 tokens → 壓縮一次，仍不足 → 本機 ContextOverflow。
density 校準規則

E ≥ 300 且伺服器輸入 P > C → 觀測值 = min(3, (P − C) / E)。比目前密 → 立即採用；較稀 → max(1, 0.8 × 舊值 + 0.2 × 觀測值) 平滑。只修正估算，不取代伺服器 tokenizer。

橫向：單回合結果的三道判斷

規則觸發情況處理方式
file讀大型檔案；PDF／影像一律走文件路徑read 先處理：一般文字 → 規則摘要；文件 → 解析子代理。
result其他單筆工具結果超預算如大量命令輸出、搜尋結果；本輪總量小也先外存。
turn多筆合計超本輪預算從未外存且大於摘要預算者中，最大筆優先；實際摘要大小受估算影響。

舊版 v1（已移除）的缺口：單一摘要、每筆舊結果只看前 2,000 字、失敗時截短 → 長任務壓縮後流失細節。現行 runtime 改為主題筆記、失敗不截短；2,000 字前綴限制仍在。詳見 07 · 長任務記憶：摘要 → 主題筆記。
