12 · 從方法找到程式

責任索引與閱讀檢查表

問題

從方法找到負責的程式與測試，並避開常見混淆：存過≠看得到、能力≠設定。

核心想法

以「問題 → 主題 → 程式」串起文件，再列每個模組的邊界與入口。

依據

各主題實測可用 repo 內評測腳本重跑；行為由對應回歸測試覆蓋（見 ③）。

問題：方法與程式之間需要一張地圖

文件以問題為軸，程式以模組為軸；改行為前先確定問題、負責模組與保護它的測試，否則只修表面。

  • 分清能力與策略W 來自部署；輸出、保留、分塊＝W 內的用法。
  • 分清歷史與新結果舊對話 → 壓縮；本輪大量內容 → 外存＋按需讀取。
  • 分清主代理與解析子代理子代理無主對話，不接管完整任務。
  • 分清三種使用層CLI 對話：篩選過的 web_search；工作流程：只有 web: 步驟；Studio：無網路、無 shell。
  • 分清 schema 與 viewschema 定回傳內容、嚴格驗證；view 只管呈現，載入時對照。
  • 分清完整紀錄與目前上下文磁碟內容不會自動全數進入下次請求。
  • 分清取消與回滾補齊工具結果只維持協定，不撤銷已發生的外部變更。
  • 分清可追查與保證正確紀錄、頁碼、全文路徑供核對；內容仍需驗證。

  • 壓縮與記憶測試：test_topic_compaction.py、test_new_memory_runtime.py、test_requirements_and_file_writes.py（固定需求、分段寫檔重試、送出前檢查）。
