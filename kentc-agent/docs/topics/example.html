11 · 串起整套方法

一份掃描發票，從檔案到可核對的回答

問題

各主題分別解一個問題；實際任務同時觸及所有限制：視窗、影像能力、不完整文件、需計算的數字、須寫出的檔案。

核心想法

以一份掃描發票走完能力、證據、上下文、核對、交付五道邊界，標出每道由哪個機制負責。

依據

教學情境，非實際執行紀錄；各邊界的實測或測試見對應主題「依據」段（見 ③）。

問題：一個小任務就同時碰到所有限制

「確認發票編號與總額，寫成摘要」：掃描檔無文字層 → 需影像能力；多頁 → 可能超出預算；總額需加總 → 不能心算；摘要須實際存檔 → 不能只宣稱完成。任一步交模型自行判斷都可能無聲出錯。

核心想法：一份掃描發票，依序通過五道邊界

重點在資料經過的邊界；不假設模型看到圖片就讀對。

輸入與目標

evidence/invoice.pdf → 摘要存至 reports/brief.md。

能力邊界

OpenAI 路徑由伺服器取得部署視窗；Qwen 用內建 60k 或部署覆寫值；視窗無效即停止。影像能力依 provider 規則；設定或相容性假設 ≠ 部署實測或辨識正確的證據。

證據邊界

主代理呼叫 read；掃描頁無可用文字層 → 預設自動渲染，模型可收影像時附頁面影像；文件子代理以預算內材料轉錄，保留頁碼。

上下文邊界

轉錄與摘要保存後，主代理先收摘要＋全文路徑；需原句 → 讀全文分頁，或以 question 向原 PDF 查特定事實；不把所有頁面反覆塞回主對話。

核對與交付邊界

核對引用位置；加總用工具；數字模糊或矛盾 → 明確保留疑點。保存成果後，以實際工具結果或 Runner 輸出確認檔案已寫出。

保障的是流程可控、可追查，不是模型永不犯錯。 視窗為偵測值；token 大小為估算；轉錄、摘要、推論仍須對照來源。

依據：每一道邊界由哪個主題支撐
