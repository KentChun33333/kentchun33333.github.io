06 · 工作區與工作階段，不是長期記憶系統

「存在哪裡」與「模型看得到什麼」是兩個問題

問題

「記憶」同時指工作區檔案、對話紀錄、目前上下文、外存結果與快取。混用 → 誤以為「存過」＝「模型看得到」，或多一個資料夾＝多一種長期記憶。

核心想法

每層明確界定：保存什麼、是否自動送進模型。只有「目前上下文」是模型本次所見；其餘層皆由工具按需讀回。

依據

歷史實測（現行 runtime 前身 v2）：每次 STR 任務寫出 5 份主題筆記，模型直接讀索引 0 次、讀主題筆記 0 或 1 次：存於磁碟 ≠ 被使用（見 ③）。

問題：「存過」與「看得到」常被混為一談

視窗有限 → 舊對話、大型結果、文件解析、追蹤紀錄移到磁碟，下一次請求只帶一小部分。統稱「記憶」導致兩種錯誤：以為模型知道（實際只在磁碟），或「記憶不夠」再加一層儲存（實際是模型不回讀）。

核心想法：每一層只負責一件事

目標是檔案與 session 的可恢復狀態；operation 資料夾不帶來跨任務知識庫、語意檢索或永久記憶。

各層責任不同，不應統稱「記憶」
層次保存什麼是否自動送入模型
工作區 Workspace輸入檔、參考材料、程式、成果；工具按需讀寫否。 在資料夾 ≠ 在提示中
工作階段 Session附加式 JSONL 對話、usage、壓縮紀錄、固定需求（requirement 紀錄）；可載入恢復只投影目前有效上下文，不重送全歷史；固定需求原文每次請求都送
目前上下文 Live context系統提示、工具 schema、摘要、保留訊息 → 下一次請求即模型本次所見。 同 session 舊原文可能只剩摘要
大型結果 Operation artifacts單次工具呼叫的 full.md／來源參照、digest.json通常只送摘要＋路徑，全文需再讀；不取代完整 session
操作追蹤 Trace輸入概況、模型回覆、工具結果、耗時、子代理關聯等除錯證據否。預設啟用、可關閉；未持久化 session 不建一般 trace 檔
文件快取 Cache可重用的文件答案、轉錄、摘要，免重複解析命中時由讀取路徑使用；非跨 session 知識記憶
主題筆記 Topic notes壓縮時寫出的 Markdown 筆記＋_index.md，位於 .kentc-agent/memory/<session>/<世代>/；每世代不可變、SHA-256 驗證否。 上下文只帶索引路徑＋≤ 8 個主題名；內容須模型自行 read／bash
<workspace>/
├── evidence/                     # 原始證據（使用者自訂）
├── reports/                      # 交付成果（使用者自訂）
└── .kentc-agent/
    ├── sessions/<檔名>.jsonl     # 檔案標頭記錄 session ID S
    ├── traces/S.jsonl            # 每個 operation 的追蹤紀錄
    ├── operations/S/7/c2/
    │   ├── full.md               # 需要另存時的完整內容
    │   └── digest.json           # 摘要與來源中繼資料
    ├── memory/S/<世代>/          # 主題筆記＋_index.md（不可變世代）
    ├── subagents/…jsonl          # 各次文件解析的獨立 session
    ├── cache/documents/          # 文件解析重用結果
    ├── attachments/              # 郵件附件與內嵌影像
    ├── runs/<run>/               # 工作流程狀態與 session
    └── tmp/                      # 長命令的完整輸出等

session → operation → tool call

operations/S/7/c2/＝session S、第 7 個 operation、工具呼叫 c2 的外存結果；≠「第 7 份長期記憶」。

快取與 operation 並存的原因

快取答「此材料能否重用解析結果」；operation 答「本次呼叫產生或使用了什麼」。兩者可能各存內容，尚未合併為單一索引。

本頁僅描述既有分工；快取身分、持久化命名、長期記憶重構皆未完成。

可恢復 ≠ 逐位元重播。 session 日誌把內嵌 base64 影像換成佔位文字 → 恢復後對話內無原始影像位元；需核對則保留來源檔重讀。
