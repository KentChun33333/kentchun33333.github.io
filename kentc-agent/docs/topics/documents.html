05 · 橫向的極端：大型文件與影像

先轉換，再依預算解析；只接受完整結果

問題

單一 PDF、掃描影像或 Office 檔即可超過剩餘視窗；掃描頁無文字層，部分 PDF 只有「請用新版閱讀器」佔位文字。直接塞入 → 放不下或以錯誤內容為證據。

核心想法

轉成來源單位（頁、表格列、投影片），依當下有效預算分塊，交給隔離的解析子代理（無工具、不見主對話、每塊一個乾淨 session）。主代理只收摘要與全文路徑；不完整結果不保存。

依據

本機 W = 62,536、輸出上限 4,096：輸入預算 46,902，容得下 12k 分塊；忠實轉錄需 1.25 倍輸出，每塊實際 ≈ 3,276 tokens（見 ③）。

問題：一份文件就可能超過整個視窗

  • 放不下：大型 PDF／試算表 → 單一工具結果超過剩餘空間；即 04 · 上下文視窗「橫向」問題的極端。
  • 讀錯：XFA 表單 PDF 可能只抽得出「Please wait… your PDF viewer may not be able to display」佔位文字 → 當內容即全錯。
  • 影像不能切：文字可再分塊；頁面影像無法由文字分塊器切開。
  • 輸出也有上限：忠實轉錄輸出 ≈ 輸入或更多 → 輸入放得下 ≠ 回覆放得下。

核心想法：轉換、依預算分塊、隔離解析、驗證後才保存

文件子代理與主代理共用模型 client、預算與 Qwen 備援；只讀本次材料與問題、回傳自足結果；重試不帶入前次半截輸出。

輸入類型如何取得材料主代理通常收到什麼
原生 PDF頁面文字；依 doc_render、文字量、視覺內容決定是否附頁面影像摘要＋全文路徑；question 指定問題、pages 選頁
掃描 PDF／獨立影像掃描頁轉影像；圖片直接讀，免包成 PDF；需視覺能力轉錄摘要＋全文路徑，或附來源位置的答案
Office／郵件／CSV／HTML轉 Markdown、保留表格位置；附件與內嵌影像另存待讀小 → 直接回文字；大 → 摘要路徑；大＋question → 解析子代理
影片／舊式 Office 二進位檔影片不支援；.doc、.xls、.ppt 須先轉新版明確錯誤，不假裝已讀

PDF 覆蓋防線：有文字，不等於讀到真正表單

XFA／佔位訊息的處理
情況處理不能宣稱什麼
已知 viewer placeholder辨識「Please wait… If this message is not eventually replaced… your PDF viewer may not be able to display…」等要求新版 viewer 的完整訊息 → 模型呼叫／快取前報錯；單獨「Adobe Reader」字樣不觸發佔位訊息不論長度皆非內容；渲染同頁只重現佔位畫面 ≠ 回復
/AcroForm/XFA 表單偵測直接／間接 AcroForm 與 XFA stream／packet array；只交付靜態頁面渲染影像，擷取文字不作證據；無視覺能力或 doc_render: never → 報錯動態 XFA 資料未檢視，可能缺漏。 限制記於來源 notes、轉錄成果、快取摘要 metadata；靜態影像 ≠ 完整表單覆蓋
明確選擇 pages只檢查、處理所選頁；快取命名空間已更新 → 舊佔位快取無法繞過檢查「所選頁可讀」≠「整份已檢視」

恢復：保留原檔，以支援 XFA 的 viewer 開啟實際表單，另存／列印為獨立 flattened PDF，核對頁面與關鍵值後重讀；改副檔名或渲染佔位頁無效。

僅涵蓋已知佔位訊息與 XFA；非動態 XFA 渲染器，不保證所有 PDF 正確解析。

  1. ① 轉成來源單位頁、工作表列區段、投影片、郵件內容；先查佔位訊息與 XFA。
  2. ② 依有效預算分塊非固定 12k；須容下提示、影像與回覆；過長文字再拆。
  3. ③ 分別解析與合併每塊、每次重試皆乾淨 session；有限分組合併；JSON 摘要重用前驗證。
  4. ④ 驗證後才保存完整且格式有效才接受／快取；截斷或無效 → 有限次重試，耗盡即報錯。

轉錄與問答，輸出需求不同

轉錄須重現原文與表格 → 另檢 ceil(user × density × 1.25) ≤ output；問答不套用。

影像 token ≠ 圖中文字長度；餘裕非完整性保證，仍須檢查完成原因。

放不下時，不默默省略證據

單張影像超出預算或筆記無法合併 → 報錯；回覆截斷 → 以相同證據乾淨重試。對策：縮小頁面範圍、調整影像尺寸或輸出策略。

加大硬視窗需改部署；重試、視覺輸入、格式驗證皆不保證內容完整或正確。

12k 分塊上限 ≠ 單次可讀 12k

預算示意 · 不是 tokenizer

W、O 預設取「上下文」計算器最後設定值，可改。user：假設的單一請求內容（任務、標題、文字、影像）；fixed 以 100 tokens 示範，非由實際文件計算。

展開文件預算公式
output = min(O, floor(W / 2)) reserve = max(max(output, 1,024) + M, min(16,384, floor(W / 4))) input = W − reserve ceil((fixed + user) × density) ≤ input user ≤ doc_chunk_tokens（預設 12,000） 轉錄另需 ceil(user × density × 1.25) ≤ output

另受每塊影像張數上限（預設 4）約束。程式以實際完整提示估算分塊，不用 fixed = 100。output 為規劃保留量，不保證實際產出。

依據：預算計算與實際執行

以本機部署代入上方公式（density = 1）
