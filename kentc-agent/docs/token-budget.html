02 · 設定上限與有效值分開看

這一輪每項額度是多少？

改動上方欄位即可更新。D 是部署上限，W 是主代理工作視窗。A 是可分配給工具結果的額度。所有除法會取整數，表中的 words、字元與 tokens 各自標示。

主代理額度與觸發條件
項目設定或邊界本輪有效值如何決定

工具外存判斷採「超過」門檻。寫入成功後會按當時的剩餘空間再判斷參數門檻。A 至少為 128 是程式採用的分配下限，即使當輪已接近超限也可能顯示這個值。能否送出仍由完整請求預檢決定。

字數與 token 是如何估算？

T 使用最新可用的伺服器 usage 作錨點，再估算其後訊息。沒有錨點時，一起估算固定提示、工具 schema 和有效訊息。density 由伺服器輸入量校準。工具文字大小用字元數除以四，再乘上 density。程式也會估入圖片與工具參數。

完整請求預檢另外計算 Q，並扣除安全餘裕 M。Q 太大時，會嘗試強制壓縮；仍無法提供最低回覆空間就回報超限。伺服器另有自己的 tokenizer 與容量限制。

03 · 調整 context_budget_tokens 時

哪些額度另有自己的規則？

限制目前行為
設定上限max_output_tokens、big_result_tokens 等設定保留原值，有效值在使用時依空間縮小。各額度有自己的公式，增加視窗後可能先碰到設定上限。
最低門檻回覆空間低於 1,024 tokens 時先嘗試強制壓縮，完整請求預檢低於 512 時再走恢復判斷。成功寫入參數的外存門檻最低為 512 tokens。
固定要求與摘要輸入有效的固定要求合計上限為 4,000 字元。摘要器接收單筆工具結果的開頭最多 2,000 字元，保留省略量標示。這兩個字元限制保持固定。
文件解析子代理文件預算採部署上限 D，自行保留輸出與安全空間。doc_chunk_tokens 預設 12,000 是分塊上限，還需檢查整份請求與轉錄擴展。主代理的工作上限 B 適用於有 runtime context feedback 的代理。
TPM、點數與供應者限制tokens_per_minute、供應者的輸出與速率限制、可用點數各自生效。工作視窗變動時，這些配額維持自己的設定和供應者規則。
