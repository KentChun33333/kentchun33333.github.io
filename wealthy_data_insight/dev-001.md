# DEV-001 — Human-guided asynchronous wealth intelligence flow

## Polished product request

Redesign the Wealth Intelligence Agent as a three-page, case-based workflow:

1. **Page 1 — User entry and Case Management**
   - Let the user start an intelligence case with a natural-language question.
   - Let the user select the permitted data sources, reasoning capacity, lookback period, and related topic.
   - Keep supporting-document upload optional and visually secondary.
   - Show a Case Management table containing case ID, topic, owner, created time, last run, current stage, selected sources, lookback period, status, and the latest Summary Report.
   - Every asynchronous run must create an auditable case event and return to this table.

2. **Page 2 — Data-capability discovery and query-boundary design**
   - Present what each selected source can provide at a safe, high level.
   - Use visualizations to help the user discover useful dimensions before narrowing the query.
   - Do not expose raw transaction-level data, document key-value dumps, or ungoverned holdings details.
   - Make the important configuration pillars foldable: human objective and hypothesis, source capability, relationship/evidence rules, population and scope, lookback boundary, validation/guardrails, requested visual outputs, and the Summary Report / agent trace.
   - Add a clearly visible right sliding prompt panel with exactly two actions: **Finetune** and **Next**.
   - **Finetune** starts an asynchronous manager run, shows progress, and returns to Case Management with an updated Page 2 boundary. **Next** advances the approved boundary to Page 3.
   - Attach the active case context automatically so the human enters only the requested delta, minimising prompt tokens.

3. **Page 3 — Cross-source insight report**
   - Combine the approved Page 2 boundaries into a cross-source insight report.
   - Show evidence lineage, confidence, source coverage, key findings, client/portfolio-level implications, and recommended human actions.
   - Add a right sliding panel with two explicit actions: **Finetune** and **Done**.
   - **Finetune** submits an asynchronous Page 3 refinement run, returns to Case Management, and creates a new report version when reopened.
   - **Done** freezes the current case/report version. A frozen case is read-only and preserves its final Summary Report and metadata.

## Terminology decisions

- The generated prompt and execution trace are called **Summary Report / Agent Trace**. Do not label this area “generated prompt” in the user-facing product.
- **Case** is the durable business object.
- **Case Event** is one user action or asynchronous run attached to a case.
- **Report Version** is the immutable Page 3 output produced by a completed run.
- **Finetune** creates a new case event and report version; it never silently overwrites an earlier result.
- **Done** freezes the case and prevents further mutation without an explicit reopen action.

## Source visibility contract

| Source | User-facing Page 2 capability | Safe granularity | Explicitly out of scope |
| --- | --- | --- | --- |
| CRM | Profiles, relationships, portfolio roles, client groups, declared suitability context | Profile → client → portfolio | Raw transaction-level detail and unrestricted personal-field dumps |
| FileNet | Available document types, document counts, client/portfolio coverage, extracted themes, evidence confidence | Document type → client → portfolio | Full key-value extraction, document-wide raw text, unrestricted page-level content |
| HELIOS | Previously processed case types, supported client/portfolio analytical coverage, result categories, model readiness | Case type → client → portfolio | Underlying model detail, raw holdings/positions, unprocessed source records |
| T24 / account systems | Account relationship coverage and permitted aggregate account context | Client → account relationship / aggregate | Raw transaction stream unless separately authorised and explicitly scoped |

Every source capability card should answer: “What question can this source help answer?”, “At what aggregation level?”, “What evidence is available?”, and “What is intentionally withheld?”

## Async Manager contract

The Async Manager owns execution, progress, retries, provenance, and return routing. A run should contain at least:

```text
case_id, event_id, parent_event_id, report_version_id
actor_id, created_at, started_at, completed_at
stage (P1_ENTRY | P2_DISCOVERY | P3_INSIGHT)
action (START | QA | FINETUNE | DONE)
topic, question, lookback_period
selected_sources, capability_boundary, relationship_rules
human_hypothesis, guardrails, requested_visuals
status (QUEUED | RUNNING | NEEDS_REVIEW | COMPLETED | FAILED | FROZEN)
summary_report, evidence_manifest, confidence_summary
```

The right sliding panel must submit this contract through the active case context. It must never run a prompt outside a case or bypass Case Management.

## Scenario scope

- `s1.html` — Shared Entities + Direct Relationships.
- `s2.html` — Next-Generation Client Identification.
- `s3.html` — Thematic Investment Opportunities from RM Meetings.

Each scenario page explains its question, source capabilities, expected Page 2 configuration, Page 3 insight, asynchronous feasibility, and hard constraints. The first scenario remains the fully demonstrated v3 path; the other two are implementation-ready designs.
