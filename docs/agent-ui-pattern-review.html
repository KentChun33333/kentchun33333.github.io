Comparative design review · source-based

Two agent experiences.
One review pattern.

AURA Wealth Intelligence v3.3 and TER / STR v15 use the same interaction grammar: frame a case, expose agent work, let a person shape the evidence, then deliver a traceable decision. The shared tactic is progressive disclosure with human authority—not a single opaque “AI answer.”

Shared UI tactics

The same visual mechanisms serve different outcomes. Each item below pairs an observed wealth implementation with its TER counterpart rather than treating the two products as identical.

01

Three-stage journey, one decision at a time

Progressive screens prevent the result from arriving before the analyst can inspect its basis.

AURAFrame question → shape search → review insight; case management keeps requests reopenable.
TERSubmit case → review / correct extracted evidence → review findings and next step.
02

Agent-work as an inspectable transition

A staged simulation bridges intake and output with named work, intermediate results, progress, and manual frame controls.

AURAWorkforce + live stage for mapping the query and running deeper analysis; source cards and result memory.
TERAgent workflow + reasoning canvas for extraction, investigation and refinement; retained results and evidence QA.
03

Evidence beside the interpretation

Keep the answer close to the source it depends on; allow deeper inspection without crowding the main view.

AURASource layers (CRM, FileNet, T24, HELIOS), relationship graphs, selected-client proof flow, provenance modal.
TERExtraction confidence, raw-document viewer, risk cards, evidence chains and appendix reports.
04

Human feedback changes the next view

The side rail is a control surface, not a comment box detached from the workflow.

AURALookback, AUM and region filters reshape the search view; report-depth / graph controls change presentation.
TERAnalyst can correct an extraction, inspect its source, and request targeted refinement; the report reflects the review path.
05

Top-line first, proof on demand

A concise recommendation comes first; drill-down reveals the supporting reasoning and caveats.

AURARanked target clients lead into a selected-client graph, rationale and evidence chain.
TERDecision summary leads into risk cards, transaction evidence, appendices and a human review panel.
06

Use state to expose what is still unknown

Make selected, pending, challenged and reviewed states distinguishable without requiring animation.

AURACase / scenario selection, intelligence layers, query-scoping controls and selected target persist across views.
TERLow-confidence fields, human-corrected values, open-source caveats and Partial → Full Exit refinement are visible.

What to reuse

A practical synthesis for another agent UI—without copying the wealth and compliance domains into one product.

Keep the shell; vary the evidence

  • Use intake → inspect → decide as a stable information architecture.
  • Keep the agent trace adjacent to concrete intermediate results.
  • Show what a human edit changed, which evidence was retained, and the new output.
  • Make source inspection available at the exact finding it supports.

Do not collapse the domains

  • AURA ranks relationship opportunities; TER tests financial-crime indicators.
  • AURA’s target selection and TER’s exit recommendation are different decisions.
  • A visible confidence score is not proof; retain source type, gaps and review status.
  • Use replayable animation as explanation, not as evidence of real-time processing.
Implementation boundary. Both reviewed files are self-contained interactive demonstrations with fixture-driven content. TER explicitly labels simulated open-web material; example domains and mock evidence links are not verified external sources. The schema above is a proposed review vocabulary, not an existing endpoint or guarantee of persistence.
